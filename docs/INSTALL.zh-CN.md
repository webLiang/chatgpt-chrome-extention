# 本地加载 Chrome 扩展并连接 Codex

[项目首页](../README.zh-CN.md) · [English](INSTALL.md)

本指南使用 **Codex 桌面应用已有的 Chrome 原生连接**。Chrome 加载本项目的 `extention/`，扩展通过桌面应用管理的 Native Messaging 宿主连接。这里的目录名就是 `extention`，请保留拼写并选择正确目录。

无需额外安装语言运行时、依赖或独立 MCP 服务。扩展直接复用桌面端现有通道；Codex 的正常登录与功能权限仍然适用。

## 1. 确认当前版本和前提

需要本机安装并能正常使用的 **Codex 桌面应用**、Google Chrome，以及当前桌面应用版本支持的 Chrome/电脑操控能力。在 Codex 当前版本提供的浏览器或电脑操控设置入口中，确认 Chrome 能力已经启用，并完成应用要求的扩展或宿主设置。设置入口及名称可能随版本变化，本指南不假设固定菜单位置。

本指南记录的兼容性环境为 **macOS + Google Chrome**。不能据此保证其他 Codex 版本、登录方式、系统、受管设备或 Chromium 浏览器可用。Manifest 声明的 Chrome 116 下限不是完整兼容性测试结果。

本次实测记录：

2026-10-27，用户确认已手动重载，Chrome 扩展详情显示 `1.26.1020.11845`。重载后，现有 Chrome `extension` 通道成功枚举实时标签，并读取已打开的公开测试页面标题与正文。新版版本由用户确认，实时标签及公共页读取由工具完成。

原生连接还需要桌面应用安装并管理的宿主 `com.openai.codexextension`。扩展可加载不代表该宿主已经安装或可连接。若当前桌面版本没有 Chrome 能力，应先处理客户端支持问题；增加自定义 MCP 项不能代替这一步。

## 2. 核对扩展与宿主身份

将整个项目放在长期保留的本地目录，避免之后移动或删除。项目中用于本路线的文件为：

```text
项目目录/
└── extention/
    ├── manifest.json
    ├── background.js
    └── 其他扩展资源
```

当前目标扩展的静态信息：

- Manifest 名称：`ChatGPT`
- 扩展版本：`1.26.1020.11845`
- Manifest 公钥对应 ID：`hehggadaopoacecdllhhajmbjkdcmajg`
- 连接宿主：`com.openai.codexextension`

这些信息用于核对，不是连接成功证明。Chrome 加载后的 ID 应与上述 ID 一致；原生宿主的 `allowed_origins` 也应允许 `chrome-extension://hehggadaopoacecdllhhajmbjkdcmajg/`。如检查宿主注册内容，只读核对即可。不要为了让不匹配的扩展接入而改宿主白名单、manifest 公钥或 Codex 认证配置。

macOS 上 Google Chrome 的用户级宿主注册通常位于：

```text
~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.openai.codexextension.json
```

这是排错时的核对位置，不是要求手工创建或覆盖该文件。应用管理的安装位置可能不同，应以当前桌面应用实际安装和支持方式为准。

## 3. 处理同 ID 的已有扩展

开发副本使用的 ID 与商店版 ChatGPT 扩展相同。**同一 Chrome 配置中，同 ID 的商店实例和已解压实例不能作为两个独立扩展并存。**

先在 `chrome://extensions` 查看是否已经有同 ID 实例。若需要切换到本项目的本地副本，应先保存必要的用户信息，再有针对性地移除或按 Chrome 提示替换这个实例，然后加载本地目录。不要批量删除扩展、浏览器配置或应用文件。

移除、替换和重新安装可能影响扩展设置及本地数据，本项目不能保证它们被保留。若要保留现有商店版使用方式，先不要替换；可以继续用商店版，通过实际连接测试判断是否需要本地副本。

## 4. 在 Chrome 加载 `extention/`

1. 打开 Google Chrome，进入 `chrome://extensions`。
2. 开启「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本项目根目录下的 **`extention/`**。不要选择项目根目录，也不要选择旧的 `local-chrome-mcp/extension/`。
5. 确认 Chrome 显示名称 `ChatGPT`，ID 为 `hehggadaopoacecdllhhajmbjkdcmajg`，且没有加载错误。

例如，项目保存在下面的位置时，应选择：

```text
/path/to/chatgpt-chrome-extention/extention
```

将 `/path/to` 换成自己的实际保存位置。加载之后保持该目录存在；搬迁目录需要重新指定加载位置并重新验收。

若已经手动完成本次重新加载且 ID 正确，直接进入第 5 节，不需要重复移除、替换或重载。

## 5. 在 Codex 使用现有 Chrome 能力

回到 Codex 桌面应用，检查当前版本提供的 Chrome/电脑操控设置，确认 Chrome 能力处于可用状态。如应用要求选择浏览器、启用扩展或重启，请按该版本的提示完成。不要覆盖 Codex 应用文件，也不要用本项目文件覆盖整个用户设置文件。

本路线使用已有的 Chrome 工具通道，**MCP 服务器列表中不需要新增 `local-chrome`**，也不要求出现旧桥接的 `browser_status`、`browser_tabs`、`browser_call` 三工具。工具名称和呈现形式由当前桌面应用版本决定。

若是在首次启用 Chrome 能力后继续使用一个早已打开的会话，该会话可能没有取得新工具。按当前客户端支持方式刷新能力，必要时新建会话。新会话只是工具可用性的排查步骤，不能代替扩展和宿主连接检查。

## 6. 验证真正的浏览器连接

准备一个普通 Chrome 窗口，手动打开公共测试页，例如 `https://example.com`。通过 **Codex 当前已有的 Chrome 工具**完成以下检查：

1. 读取工具能够提供的浏览器或扩展清单，核对当前连接的浏览器实例及扩展 ID `hehggadaopoacecdllhhajmbjkdcmajg`。只使用当前版本实际提供的检查能力；如没有扩展清单接口，在 Chrome 扩展页核对 ID，并记录工具侧无法直接核对的限制。
2. 列出 Chrome 的实际标签页，确认出现刚打开的公共测试页。核对窗口或浏览器实例，避免把另一个配置中的页面当成本次结果。
3. 使用同一 Chrome 工具选定测试标签，读取实时页面标题、URL 和正文。`https://example.com` 应能读到网页中的 `Example Domain`，而不是只依据 URL 或常识推测内容。

静态读取本项目文件、manifest 或宿主 JSON 只能证明文件内容，不能证明在线浏览器可用。设置开关、绿色状态点、插件弹窗、Service Worker 状态或进程存在也不能单独证明整条链路接通。只有通过实际 Chrome 工具列标签并读取测试页，才完成这里的连接验收。

若工具报告当前版本不支持 Chrome、身份不允许、宿主未连接或没有工具，应记录实际错误，不把配置完成写成连接成功。不要通过改公钥、宿主白名单或认证文件解决账户/版本限制。

可交给本机 Codex 的验证请求：

```text
请使用当前桌面应用已有的 Chrome 工具检查连接，不启动 local-chrome-mcp。
我已从本项目的 extention/ 加载扩展，目标 ID 是 hehggadaopoacecdllhhajmbjkdcmajg。
请核对可见的浏览器/扩展信息，列出当前标签页，选择我打开的 https://example.com，读取实时标题、URL 和正文。
如当前工具或版本不支持，请明确报出限制；不要通过读取本地文件或网页常识来声称在线验证成功。
不要重复重载我已经重载的扩展，不要更改 host、key 或账户认证。
```

## 7. 排错

**Chrome 显示的 ID 不一致：** 确认加载的是本项目 `extention/`，不是旧桥接扩展或其他目录。检查所拿到文件是否完整且来自预期来源；不要修改宿主白名单去接纳不同 ID。

**Chrome 提示同 ID 扩展已存在：** 回到第 3 节，只处理该 ID 的现有实例。关闭开关不等于安装了另一个实例；按 Chrome 的替换提示或针对性移除后加载，提前考虑设置和数据丢失风险。

**找不到原生宿主或连接断开：** 先使用当前 Codex 桌面应用提供的 Chrome 设置、扩展管理或修复流程，必要时保存工作后重启桌面应用与 Chrome。核对应用仍在有效安装位置、宿主允许的 ID 一致。不要手工写入未知宿主、运行旧本地桥接安装器或覆盖应用二进制文件。

**仍出现账户、认证或版本不支持错误：** 本地加载扩展不解除桌面运行时的认证和可用性要求。按当前客户端支持方式排查；此时应保留实际报错，不宣称已连接，也不改认证文件或 API Key。

**能列标签但读不到测试页：** 核对选择的是普通 HTTP/HTTPS 标签、正确浏览器实例和已授权范围；内部页、扩展页、无痕窗口、受管页面或浏览器限制不能用公共测试页结果概括。先以第 6 节公共页完成最小验证。

**服务列表里只有旧 `local-chrome`：** 它属于先前独立桥接方案，不是本指南的验收对象。本路线使用桌面应用已有 Chrome 能力，不需要启动它；不要根据它是否在线判断原生通道状态。

## 8. 停用本地副本与恢复

停止正在进行的浏览器任务，在 Chrome 的扩展管理页移除本次加载的 `hehggadaopoacecdllhhajmbjkdcmajg` 本地副本。然后通过当前 Codex 桌面应用的浏览器管理流程或官方商店入口恢复所需扩展，并重新做标签列表和公共页面读取验证。

不要批量删除 Chrome 扩展、浏览器用户数据、Native Messaging 宿主或 Codex 设置。移除本地副本不要求移除桌面应用管理的原生宿主。恢复商店版也不能保证此前被移除实例的设置和本地数据恢复。

浏览器工具能够访问当前用户授权的网页，包括已登录页面。安装完成后仍应按具体任务授权操作；超时、取消或界面状态变化不证明此前已发送的网页动作被撤销。
